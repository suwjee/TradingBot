# E — Recursive candidate formation, ownership and numbering (V3)

**Conventions:** B = bullish, R = bearish. A strict trend stop means Low < level for B, High > level for R; improvement uses the same predicate. Main source identity and exact event chronology are separate. Preserve Decimal representation, operation order and stable ordering. Required record fields/defaults are in [record interfaces](../../Contracts/Declared_Record_Schemas.md); shared searches in [Index and cache contracts](20_Indexes_And_Caching.md). Procedure labels identify semantic operations, not required implementation symbols.


## E-M01 — Module boundary and initialization

Consume accepted/provisional S roots, trend/opposite native Reactions and Resets, chronology, initial accepted A Order ledger, blocked First gates, independent Order_B legs and explicit sequence-priority service. Invalid S identity set identifies calculation evidence without native creation rights. Construct full/bounded range, main directional extreme index or sparse table and independent physical audit state. Empty candidate collection returns empty numbered result. Do not use lifecycle display filtering as a substitute for E candidate acceptance.

## E-M02 — One global Order race per stopped parent

Parent (S or E) must strictly stop from its exact decision, searched over lower [max(decision,range_start),range_end). No main fallback. Collect unconsumed S Blue Orders (S only), gate-owned initial query (preserve dependency evaluation), carried-live before registering parent audit, register parent-stop cause, then query post-stop accepted stream and direct candidates. S without carried candidates bounds continuous direct selection by earliest inherited crossing or range end. E enables trend-leg continuation. These are creation/reuse contracts in [Order Audit](08_Order_Audit.md), not E-created geometry.

Merge crossed-only direct, inherited, carried and post-stop accepted by (exact strict Order stop, negative physical First index). Group post-stop stream by equal stop and reorder each group by this same key; do not reduce each route prematurely. Equal merge keys preserve route order. For each candidate, source = directional extreme over COMPLETE main candles containing parent stop through max(parent stop,Order stop), inclusive. Earliest equal main extreme wins. Reject Order whose only creating cause is disowned S or prospective same-source S under native ledger predicate. First remaining candidate wins. Source price is frozen; decision = max(parent stop, Order exact stop), main index mapped from that instant. Output E with parent identity/type/price/stop and full native Order identity/geometry/causes plus source and decision. If no accepted crossed Order, no E.

## E-M03 — Provisional discovery and candidate chains

First register stopped S parents in sorted source order before recursive discovery; then each stopped S opens independent chain of its family, number starting 1. Stop repeatedly at each E decision and run same race. Terminate when no stop/no child or duplicate source index in current chain (not a fixed depth cap). Retain every candidate, not just earliest root. If invalid S roots conflict with opposite-family E continuation at their source, discard whole affected chains. Reconciliation alone owns final family/number. Root continuation from consumed S evidence requires independent cause if invalid S and respects sequence reset between parent and child; see lifecycle.

## E-M04 — Reconciliation algorithm

Maintain min-heap of source groups ordered by earliest source time, earliest decision, source index; numbered sequence, accepted source identities/times, active E list, optional sequence_start. At each source:
1. Reopen parent Order race if a previously usable Order has become only-disowned-S and parent is eligible. In checkpoint replay this forces complete reconciliation restart; otherwise enqueue regenerated candidate with same physical ownership checks.
2. Reject invalid Order (disowned S, gate-owned earlier Order blocking, invalid S root with no independent cause) and inactive parent. S parent must exist and not itself be accepted E; cannot predate hard sequence boundary via own/A source. Against preceding numbered E, permit rebuilt S with own source later and A source not earlier, or an unused Red S dominating Blue E with earlier source. E parent eligible if boundary source, active physical parent, or specifically traced skipped invalid parent; actual winner still requires active physical parent or boundary.
3. Remove S candidate when it strictly stops an active E after that E decision, and owner is Red or candidate Blue, and an owner child decision at/after candidate decision exists. Prefer subset not blocked by a still-unaccepted later Red S before Blue E parent stop, if subset nonempty.
4. Choose highest parent ownership priority (S blue 1,E blue 2,S red 3,E red 4, actual active E family when present); ties earliest decision, then parent stop, then encounter. Reject if winner's E parent is not actually active or boundary.
5. Identify active E strictly stopped by winner price and strictly later decision. Number/family: actual Red parent -> Red, max stopped Red+1 or 1; otherwise any stopped Red -> Red max+1; otherwise Blue parent -> Blue max stopped Blue+1 or 1; otherwise stopped Blue -> Blue max+1; else original family/1. Remove all stopped active identities; append frozen replaced family/number. If source is sequence reset, clear active and set sequence_start instead of adding. Only regenerated winners discover additional descendants; enqueue later source only.
6. Collect accepted lineage stop evidence (seen identities). Preserve native numbered tuple for cache; project E parent type to StopAll only when parent source in sequence reset map. No rewriting physical Order or geometry.

## E-M05 — Final conflicts, restoration and audit

Same physical (source index,time) conflict: greater E family priority wins, same family higher number, equal keeps first. Final order source time,index,decision event. Consumed S evidence may replace descendants only when new direct continuation decision strictly earlier than existing earliest child; keep owner, remove descendants by ancestry walk, resolve same-source conflicts. Independent S root restoration considers only roots whose S parent still accepted and not dominant E source; use heap of roots, rerace when only-disowned cause, for a same-S-parent match, remove the earliest existing result by (decision_event_time, source_time) using object identity and append the restored root without comparing its decision against the removed result; otherwise apply the exact source/parent duplicate gate. E40 retains a monotone dominant-source set until final conflict resolution. Rebuild canonical accepted ledger after branch replacement/restoration as required by the owner. For the StopAll donor input only, TB74 keeps original accepted E at occupied exact (source_index,source_time) pairs and adds restored roots only at missing pairs; do not replace an occupied donor with the independently restored root. The restoration helper may itself replace same-parent E or update accepted identity state, so this donor filter is a distinct bridge step. After LC40, restore roots again and ensure accepted audit before Order_B discovery; the disabled path still restores and ensures audit. Historical valid cause retention is ledger-owned.

## E-M06 — Continuation contracts and errors

Live E history scoped by first main/timeframe and feedback scope; track dirty instant, stop progress, main extremes, zones, exact candidate evidence/steps, accepted identities. Reuse settled strict-before-dirty evidence only under keys; re-open forces full race restart. No fixed recursive cap; duplicate sources/cycle seen sets and strictly advancing event gates bound intended native paths. Unknown priorities/directions, missing records and invalid bounds follow explicit errors; no broad catch other than reopened reconciliation control. Exact cache procedures below.

## Detailed E procedures

### E01 — LiveEContinuation.__init__
Initialize chronology, scope, dirty time, main index null. Fresh current and previous dict pairs for stops, extremes, zones, reconciled results, scoped reconciliations. No external state.

### E02 — advance
Input chronology and keyword first_dirty_main. Require nonempty times and index 0..len inclusive else ValueError. Scope=(first main time,timeframe), dirty=time at index or last+timeframe. Same scope retains old current dicts as previous; changed scope uses empty previous dicts. All five current dicts fresh; clear main index; retain chronology and scope. No calculation. Scope equality alone is not proof of market prefix; caller supplies dirty evidence.

### E03 — _dirty_time
Require detector.chronology is retained chronology and dirty non-null, else ValueError. Return dirty.

### E04 — first_stop
Inputs detector,start,level,keyword less and search callback. Validate via E03. Key=(less,start,Decimal level) (numeric equality, not string). Use current progress else prior; prior with null event OR event>=dirty becomes new progress(min(old scanned_until,dirty),null). Store non-null progress in current. If event exists return only if event<range_end else null. Else resume start=max(start,scanned_until). Start>=range_end => null. Call search(start,range_end,level); store progress(event or range_end,event); return event. End exclusive through search; no coarse fallback. Fresh search callback output is stored and returned unchanged; the range-end check is on retained events, not a fresh callback postcondition.

### E05 — extreme
Validate E03; key=(direction,start index,end index). Current hit else prior only if main time at end<dirty. If absent, lazily build reaction_engine LowerTimeframeIndex over detector.candles once per advance; directional range_minimum/maximum on [start,end+1); result (integer candle.index,main time,price). Store current and return. Shared main index used for both directions.

### E06 — zone
Validate dirty. Match 9-tuple (Order number,object,confirmation,stop level/source index/source time,cross tuple,causes,cause time), assert cross non-null. Key includes detector direction,family,number,parent type,parent source index/time/string price,stop event,Order number/First/Break/mode/top source/string top/bottom source/string bottom,confirmation/string level/stop index/time/cross/causes/cause time,source index/time/string price. Use current else prior only if max(stop event,cross exact event,confirmation)<dirty. Else build E32. Store and return same selected object. Never reuse before native race selects same Order key. The key does not separately include Order direction, First/Break timestamps or box-source timestamps; consistency of selected match identity and geometry is an owner dependency. Current hits bypass the previous-generation cutoff.

### E07 — reconcile
Validate dirty. Empty candidates delegates E44 and returns numbered only. Else gather physical candidate Order identities sorted; ledger evidence per identity=(entry exists,in initial ledger,bool Order_B causes,frozenset causes or empty tuple). Group by candidate source_index, preserving candidate order, dependency tuple=(repr zone,ledger evidence,blocked-by-gate query result,sequence priority(parent_type,red),priority(parent_type,blue),parent_source_index for E else own source index). Group S parent evidence by source index with source_time,A source time,decision exact time,color. Resets frozenset items; validity=(invalid S identities frozenset,visual lifecycle starts frozenset). Evidence tuple=(groups,parents,resets,validity). Scope=(direction,live_scope); cache key=(candidate object IDs in order,groups tuple,parents tuple,resets,validity). Current or previous exact hit: save under current key/scope, restore last candidates list, accepted set and union lifecycle starts, return copied numbered list. Entry presence is non-null, but cause extraction uses truthiness: an empty mapping is present and yields false Order_B evidence and an empty tuple. Evaluate gate query, red priority, then blue priority per candidate. Group tuples retain insertion order.
Otherwise previous scoped result if any; steps empty, frontier=0, checkpoint null. If prior and validity equal: frontier=main index of dirty; compare union old/new group keys, rewind to min(frontier,changed source,all affected parent-source indexes); rewind for changed S-parent groups, symmetric difference resets mapped to main. Find lower bound previous.steps by step.source; keep preceding steps; checkpoint=step at position else last step and remove last retained step. Call E44 with checkpoint arguments. Catch only _ReopenedERace, clear steps and restart E44 without checkpoint. If reconciliation did not dynamically reopen, save immutable _ReconciledE (original input candidates tuple,numbered tuple,accepted,lifecycle starts,evidence,steps,native tuple), both maps point same record. Return numbered list. No broad exception suppression. On validity mismatch the prior scoped result is still passed to native compute, with zero frontier and absent checkpoint. Terminal checkpoint fallback assumes nonempty prior steps; no local guard. Only first compute is caught for reopen; retry errors propagate. Frozen record does not recursively freeze evidence dictionaries.

### E12 — _main_index

### E13 — _first_cross_position
Inputs left/right positions, level, keyword less. Lower index present: delegate first_less or first_greater. Otherwise scan range [left,right), normalize Low if less else High, return first strictly < or >. Null absent. No main fallback. An indexed result (including null) returns immediately; no scan retry or local empty-range/bounds guard. ### E14 — _stop_value
Normalize attribute from policy extreme_attr, return.

### E15 — _initialize_main_extremes
Read optional chronology._e_main_extremes dictionary; use direction cache if non-null. Otherwise build normalized main directional value list, integer candle code list, E16 sparse table; if chronology dict exists store triple. Cached hit assigns shared lists/table to detector. No new dict on chronology if absent. A non-null mapping includes an empty dict. On miss, price list, code list and sparse table are assigned in that order; publish the same three references into the existing mapping. On hit, unpack all three references without copying.

### E16 — _build_extreme_sparse
Values length n, empty=>empty list. Level0 positions 0..n−1. For k starting 1 while 2^k<=n, compare previous level positions i and i+2^(k−1) over width n−2^k+1. Choose lower value B/higher R; if neither strict comparison wins choose smaller position (earliest tie). Append level; increment k. Return table. Uses exact normalized values, no price transform.

### E17 — _extreme_position
Inclusive [left,right], length=right−left+1; <=0 returns left. k=floor(log2 length) via bit_length−1; compare stored positions for intervals starting left and ending right of size 2^k. Directional strict extreme wins; equal choose smaller position. No bounds clamping here. The nonpositive-length return precedes reading the sparse table. Evaluate the first directional strict test, then the reverse test only if the first fails; if neither wins choose the smaller position (no explicit equality predicate).

### E18 — _first_parent_stop
Start=max(source_time,range_start). Nonlive E19(start,range_end,level); live E04 with less=(direction B), search bound E19. Return (clamped main index,event) on non-null else null.

### E22 — _cross_order

### E28 — _extreme_between
Map start/end exact times to clamped main indexes. Start=max(detector start,mapped); end=min(detector end,mapped); if end<start set end=start. Include COMPLETE boundary main candles, even prices after exact stop. Live E05 else E29. The start is only lower-bounded by detector start, and end only upper-bounded by detector end; after promoting reversed end to start, no second stage clamp is made. Valid stage membership depends on caller inputs.

### E29 — _find_extreme
If shared callable and valid 0<=start<=end<count, query [start,end+1), return (integer candle.index,time,value). If shared callable but invalid bounds and sparse absent initialize E15. Otherwise E17 then return cached code/time/value. No additional clamping. The shared guard is non-null, not callable validation. Under invalid shared-query bounds, fallback initialization tests attribute presence via hasattr, not whether its value is null. With no shared query, that lazy initialization branch is not entered. Returned value is not renormalized.

### E30 — _zone
Inputs family,number,parent type/object,stop event, optional keyword e_owned_source_times null. For S only get mixin unconsumed S orders else empty. Invoke gate-owned initial Order query (result local unused but preserve call). Get carried orders, register parent audit, obtain lazy post-stop accepted stream. If S and no carried: continuous deadline=min(exact stop of inherited crossed entries,default range_end); otherwise null. Get direct candidates from mixin order_candidates(stop_event,deadline,allow_bounded_continue=S,allow_trend_leg_continue=E,e_parent=E). Choice key=(exact crossing event,negative integer Order First). Sort crossed-only direct/inherited/carried independently by key; merge those streams with E31 post-stop stream in route order on exact ties. Owned sources = supplied set if non-null, else source times from accepted E identities. Iterate choices: prospective source E28 from stop to max(stop,Order cross event); skip if mixin says Order created only by disowned S for physical First/Break,owned times,prospective source time. First remaining match wins. Null if no match. Live E06 else E32 builder with selected match/source. No route-local reduction discards later First before global tie-break. Query/registration order is observable: the unused gate query must execute; carried is obtained before audit registration, then the post-stop iterable is acquired before direct candidates. S deadline uses truthiness of the entire carried collection, not crossed count. The first three crossed streams are sorted eagerly in literal direct, inherited, carried order; the fourth generator is lazy. A supplied empty owned set is retained by reference, not replaced with accepted identities. Prospective source is evaluated before the disowned-S predicate, and the first survivor is returned without further candidate evaluation. No local rollback of prior ledger/cache effects on rejection or exhaustion.

### E31 — _zone.post_stop_choices
Generator over post-stop accepted stream grouped by consecutive exact stop event; sort each group by choice key from E30 (later First first), yield entries. Upstream stream order must already group equal stop times. Does not materialize all groups at once. Group consecutive equal-stop items only; the accepted owner has its own ordering by exact stop, confirmation, negative First, and E's stable per-group sort changes the secondary key to negative First. Equal merge keys retain route precedence direct, inherited, carried, accepted; within a route stable encounter order. Owner stream validity is a W2 dependency.

### E32 — _build_zone
Unpack 9-field Order match, assert cross non-null. Decision exact=max(parent stop,Order cross event), main index/time clamped via E12. Source index/time/price supplied; parent stop main index/time mapped. Return EZone fields: stored direction, family/number/parent type, integer parent source index/time/normalized price, stop tuple; stored order_direction, order number/mode, causes and parent-stop cause time, integer First/Break and times, confirmation, normalized box top/bottom with integer source positions/times, match stop level/source index/time, source tuple, decision tuple. No extra stop or source query. Read integer Order First, box top source, box bottom source and Break in that order. Main-time fields are read from detector.times at the mapped or supplied positions, not copied from Order geometry timestamps. Parent source time and source tuple are passed through. Parent price and box prices alone are normalized in this builder; match stop level, stop source index/time, causes and source price are retained unchanged. The crossing tuple contributes its exact time to decision max; EZone has no separate exact Order crossing field. No local assertion recovery.

### E35 — continuation_chain_from_s
Inputs stopped E owner,S evidence, optional independent_a_order_identities empty frozenset. S source identity=(time,integer index). If equals owner or already accepted E => empty. First strict S stop E26 absent => empty. Family string owner.family, number=int(owner.number)+1; parent initially S. Fresh chain, seen source-index set, owned times from accepted plus owner. Loop E30 with owned set; null or repeated source index stops. If E41 invalid S without other Order cause and physical Order not in independent A set, stop. If mixin sequence reset between parent source and child source, stop. Append zone, mark source/time; next E parent stop absent terminates; else update parent type E,parent,stop,number++. Return chain. No artificial depth cap. There is no separate local owner-accepted-membership gate; only the S identity is checked against owner and accepted E. The independent A membership is evaluated only if E41 is true. Reset query uses (parent.source_time,zone.source_time], excluding equal start and including equal end. E30 is invoked before repeat/cause/reset gates; its owner effects are not locally undone on rejection. Append before next stop lookup; number increments only after a non-null next stop.

### E36 — replace_with_earlier_continuation
Empty continuation => copy base. Owner ID=(index,time); map base by ID (last wins). Define E37 ancestry check. Direct E children of owner; if any choose earliest (decision exact,source time), and continuation first decision>=winner decision return unchanged copy. Else remove all descendants via E37, merge kept then continuation, E38 same-source resolve; replace accepted identities set from selected (time,integer index), return. Equality does not replace existing branch. Use the first supplied continuation element, not the minimum of that list. With no direct children, skip the decision comparison entirely. The ancestry filter has no separate check of each descendant's decision time or special exemption for the owner object; retain exactly records for which E37 is false. In normal acyclic lineage this retains the owner. Empty/equal-or-later paths do not update accepted identities.

### E37 — replace_with_earlier_continuation.descends_from_owner
Walk current while parent_type E; parent ID==owner =>true; repeated parent ID=>false; add seen, follow base map if exists else false. Non-E parent=>false. Local seen each invocation.

### E38 — resolve_same_source_conflicts
Physical identity=(integer index,time). Traverse zones; first entry wins initially; replace only E39 says outranks. Keep original encounter order of identity keys; then stable sort selected objects by (source_time,source_index,decision_event_time). No renumbering or provenance rewrite beyond choosing object. The key is integer-normalized physical index, but final sort uses each selected object's raw source_index. Equal priority with different families keeps the incumbent; priority policy itself is injected.

### E39 — resolve_same_source_conflicts.outranks
Compare shared priority("e",family): unequal higher wins. Same priority AND same family with unequal number =>higher number. Otherwise false, preserve incumbent. Uses injected priority resolver, no independent hardcoded table.

### E40 — restore_independent_s_roots
Dominant sources set(index,time); accepted S roots exclude same physical source. Select last candidate zones parent_type S, integer number=1, parent in accepted S, not E41 invalid. Result copy dominant zones. Heap root tuples(source time,index,ordinal,root), ordinal initial enumeration; known root set. While heap: pop; skip if parent ID now dominant. If native Order only by disowned S (owned times from dominant), locate first matching S via next (absence propagates), E30 replacement family/1/S/parent/old stop with current owned times; enqueue unique non-null replacement, increment ordinal; continue. Otherwise find same-S-parent zones in result. If any choose min(decision event,source time), remove by object identity, append root; else append only if no identical source/parent identity and parent type. Add root source to dominant even if not appended. Finally E38 conflicts and reset accepted identity set. No candidate-root creation from consumed S not in self.s_zones. Initial dominant and eligible S keys use integer source indices; candidate parent keys and evolving root additions use raw stored indices. The known-root set uses full record equality/hash, not source identity alone. The disowned branch always continues after the rerace, including null/duplicate replacement; next has no default. In the same-parent branch choose the earliest existing record only to identify the object to remove: there is no new-root versus existing decision comparison. Remove all references identical to that winner, not equal distinct objects, then append root. The evolving dominant_sources set is monotone: do not delete replaced winner sources; add raw root source even if no append. Final conflicts may reduce the accepted set.

### E41 — _invalid_s_without_order_cause
False unless parent type S and (parent time,index) in invalid S set. Physical Order in initial audit =>false; missing current entry=>true; truthy Order_B causes=>false. Else collect invalid S times; return NOT any cause tuple with kind parent-stop AND not (parent type S and cause[4] invalid S time). Thus independent cause permits invalid root geometry, not new invalid-S cause. Evaluate the S type before invalid parent membership, then initial membership, then current entry lookup. Empty entry is not missing; truthy Order_B causes exempt. Invalid source times discard the index. In cause scan test kind first, then S label, then cause[4] only for S; no tuple-length guard. Missing causes defaults empty tuple; explicit null or malformed cause is not repaired locally. Empty causes yield true.

### E42 — _discover_candidate_chains
First pass all sorted S: E26 strict stop; register S audit and save stopped parent for each hit BEFORE walking chains. Second pass each stopped S: family string color, number=1,parent S, fresh chain source set/list, owned times from accepted. Loop E30; absent or repeated source index breaks; append to chain and candidates, mark source/time, parent=E zone; next stop E26; absent break, else number++ and continue. Retain nonempty chain keyed original S. If no invalid identities or no candidates return candidates. Else map physical (time,integer index) of E-parent continuations to family set. Block invalid S root identities whose source has any continuation family != S color. If none blocked return candidates; else flatten only unblocked original chains in order. No sequence reset filter in this discovery loop; reconciliation owns hard gates. The first pass records every stopped S even when the inherited registration declines because of invalid identity, E ownership or reset; no creation claim follows merely from registration call. In each chain append to local/global lists, mark index/time, switch parent before next stop; increment only after next stop exists. The discovery loop has no direct E41 filter or local reset gate. The later cross-family pruning uses any unequal family, only exact E-parent candidate identities, and removes entire original root chains; preserves root and within-chain order, with no local rollback of prior ledger effects.

### E43 — _reconcile_candidate_chains
Live E07 if available, else E44(candidates)[0]. Use non-null continuation identity, not truthiness. Nonlive calls E44 without optional args, returns element zero only. No local catch, retry or fallback.

### E44 — _compute_reconciliation
Inputs candidates, keyword steps/checkpoint/previous defaults null, frontier=0. Group by source_index; heap of (min source_time in group,min decision_event_time in group,source index) for sources>=frontier; scheduled set. known=set(candidates), regenerated empty; _reconciliation_reopened=false. If checkpoint supplied restore numbered prefix from previous.native_numbered up to count and active list from checkpoint; else empty. accepted_sources=(time,index) set, accepted_source_times, set detector accepted to same set; sequence_start from checkpoint or null. Map candidates by (index,time), last wins; S map by (integer index,time), first wins. Build indexes via E45 for retained numbered; child max decision per E parent via E46 for all candidates. All candidates are grouped and indexed, including those below frontier; frontier gates only initial heap membership. Source and decision minima are computed independently and need not come from one zone. Known uses full record equality/hash; scheduled only includes heap keys. Checkpoint presence controls prefix slice and active copy, with no local check that previous exists or count is valid. Detector accepted set aliases the local accepted_sources set; accepted_source_times is separate. Candidate identity map uses raw index (last wins); S map normalizes index (first wins).
Heap loop:
1. Pop source, remove scheduled; if steps supplied append snapshot BEFORE source processing (source,count,active tuple,sequence_start).
