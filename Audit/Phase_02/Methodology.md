# Methodology and row schema

1. Resolve the latest main head and recursive Engine tree directly from GitHub. Select its 16 production and package Python blobs. Independently check local materialized byte copies against the freshly obtained Git blob SHA-1 and length, and against Phase 01 SHA-256. The local transfer medium for 15 blobs was the previously verified Golden ZIP; it was not a semantic authority or a different code version. The root package marker is empty and checked directly by its current main blob identity.
2. Parse and compile with CPython 3.13.5, without executing application modules. Enumerate AST scopes, locations, operators, control-event sites, symbol use, fields and calls; use compiler symbol tables to independently identify binding categories. IDs combine pinned file path, line, UTF-8 byte column and kind, with disambiguation ordinal where necessary. Scope IDs add the scope name. They are stable within this baseline, not across arbitrary source edits.
3. Generate a statement graph for modules, classes and function bodies. Represent if/loop outcomes, return/raise/continue/break, exception handlers, finally and with cleanup. Each expression branch or short-circuit stage is inventoried separately; statement graphs do not expand all expression evaluation order. Possible exceptions and cleanup dispatch deliberately overapproximate. Independently derive block-level graphs from compiled code objects, jump targets, exception table ranges and suspension/resume boundaries. Bytecode is not a source authority; only offsets, counts and terminator kinds are retained, not instruction streams or operands.
4. Enumerate calls and lexical, self-class and imported internal candidate targets. Builtin and external candidates are separate; unresolved dynamic/inherited targets are retained. Python shadowing, runtime binding, dynamic imports, callbacks and aliasing prevent exact complete target inference from this analysis.
5. Inventory Name/Attribute/Subscript accesses, syntactic writes/deletes, potential mutable method calls and I/O boundary names, then group by scope and symbolic name/path. A monotone may-reaching-write analysis propagates candidate definitions over statement CFG edges. It does not kill earlier definitions or prove heap aliases, call side effects or intra-expression evaluation order. Unknown entry state is explicitly retained. Imports, exception bindings, augmented assignments, comprehension first iterables, defaults and decorator evaluation have separate syntactic or compiler-symbol evidence; the lexical AST attribution is conservative, not exact Python execution scope in every case.
6. Recheck inventory counts using independent AST walks, all statement locations, unique identifiers, edges, source hashes, and cross-references. Repeat full generation in the same environment and compare output SHA-256.

## Per-module schema

Each JSON has `scope_records`, `nodes`, `branches`, `calls`, `accesses`, `effects`, `exits`, `comparisons`, `arithmetic`, `fields`, `imports`, `symbol_table`, `def_use`, `cfg`, `bytecode_summary`, `compiled_cfg`, `conservative_reaching_writes`. Column arrays define positional row fields. Local integer node indexes refer to `nodes`, and scope indexes to `scope_records`. Node IDs are the module path plus colon plus stable ID suffix; source location uses start line, start byte column, end line, end byte column. A comprehension filter uses the expression ID with a `:filter` suffix. Outcome IDs are site ID plus outcome label. `imports` rows contain node index, scope index, module name, relative level, imported name, bound alias, internal candidate path or null. CFG edges use integer node indexes or synthetic labels. Compiler block graph IDs are constant-object ordinal paths; offsets are CPython-specific. Symbol table entries carry compiler binding flags. Candidate target scope IDs can refer to another module report. `ENTRY_UNKNOWN` and `PARAMETER` are abstract markers, not literal program values.

The count of 3,133 sites includes 6 named binding events and 11 generator suspension/delegation events: 3,116 remaining decision/control sites. 6,608 outcome labels are an inventory, not proof that each is feasible, mutually exclusive, or executed. Count each syntax site once; multiple short-circuit stages may have separate labels. The 8,231 statements and 17 exception handlers are represented. Locatable AST nodes (65,842) exclude locationless operator/context helper nodes. `effects` uses flags, not a claim of proven mutation by each call. The exact source remains in main only.

No semantic rules, prices, output JSON or production code were changed. Full interprocedural dynamic resolution, exact alias analysis, path feasibility, runtime branch coverage, and semantic reachability remain unproved. These limitations are not missing files in the inventory.
