# V9 — efficient exact regression architecture (proposed, not implemented)

## Measured reason for change
500k full synthetic pair in run 45412741149 succeeded as a completed execution, Golden PASS, selected coverage INCOMPLETE. Job duration 3,107 s; observer-on times 736.444 + 683.549 s (1,419.994 s total). The remainder includes integrity scans, comparison, runner setup and artifact upload; it is not entirely engine computation. The two traces contain 6,451,099 raw events; final uploaded ZIP 1,655,684,473 bytes. Full selected comparison took about 1,046 s between both variants completing and the summary. No precise per-function profiling of tooling has yet been performed. Do not infer a speedup from these figures.

## Tiered test execution, no weakened release contract
- A: on every edit, complete official unit suites, adversarial observer/mutation tests, and exact full native output pairs on targeted fixtures and small RAW. Every changed module maps to explicit semantic/branch coverage. Live protocol and both directions included.
- B: for each optimization checkpoint, run all seven full real RAW pairs plus 100k/250k (or greater feasible) native synthetic pairs, exact stable bytes against frozen Golden, complete targeted semantic event traces for affected owners and cross-owner boundaries. Use paired unprofiled native benchmarking separately from observer overhead.
- C: final phase/release gate, full chronological million-candle native pair, full required semantic trace coverage and integrity; retain the old exact reference observer until the replacement proves equivalent. Execute maximum feasible full pair if the actual host constrains 1M; full-scale gate remains incomplete if not completed. Never substitute independent chunks that reset state or sampled events for full history. Do not infer universal state parity from finite tests.

## Replacement trace transport (test-only)
1. Profile observer and comparator separately; attribute time, bytes and memory by stage, writer, serialization and reader. Record native reference vs observer times without claiming production speedup.
2. Build immutable, deterministic, typed event encoding preserving exact Decimal tuples/strings as required by contract, numeric types, identities, direction, ordered mappings, chronology, pre/post and explicit unsupported status. Preserve raw evidence; no sorting that changes semantic order. Any proposed format change must prove exact decoding to legacy canonical bytes where applicable. Use exact byte compare for the tested event stream; hashes for indexing and locating divergence, not a sole proof of equality.
3. Capture every required semantic mutation using audited owner sites, not repeated whole-state serialization per read-only physical call. Preserve invocation evidence when semantically required; initial snapshot + ordered, complete reversible delta including removals, reorder, alias/identity and in-place nested mutation; verify replay against fresh independent authoritative snapshots at safe boundaries. Unknown mutation paths, unsupported fields and incomplete representation must fail closed. No id-only mutable memoization; large immutable inputs may be referenced only after proving immutability of elements AND container/order.
4. Merge redundant read/validation passes into one streaming validation pipeline for schema/ordinal, completeness, compressed and uncompressed hashes, references and exact comparison. Preserve every existing independent gate and error classification; do not weaken corruption tests. Validate all sidecars, including nested references and unreferenced/missing-file policy. Use bounded buffers. Chunk by EVENT COUNT with stable ordinal and byte framing, not independent candle calculations; preserve full continuity. Compress buffered lossless records with lower compression or faster codec only after measuring exact roundtrip and disk tradeoff. Use chunk manifests, byte hashes, counts, exact comparisons and first divergence diagnostics. Full trace body still recoverable.
5. Schedule two isolated sources concurrently only if measured total RSS/disk/CPU permits, or independent runners with explicitly measured artifact transfer overhead. Avoid duplicate full executions if cache key pins complete source closure, RAW bytes, settings, time range, direction, observer/comparator/schema, Python/dependency versions and environment; verify stored artifacts and never reuse stale/incomplete results as PASS. Keep unprofiled ABBA sequential on comparable host to avoid contention bias.
6. Validate replacement against old reference on both short real RAWs, controlled E/Order/Live/lifecycle/cross-direction/cache mutations and 100k, 250k complete cases. Prove same selected-event results, counts, first divergence, exact reconstructed bytes and completeness flags; deliberately corrupt values, Decimal exponent, order, nested mutation, duplicates, missing records, truncated gzip, altered refs and identity reuse. Measure before/after same-host repeated runs with peak RSS and disk. Advance scale only on proof; larger case must complete, not sample. Then perform final required V9 gates. Do not label an incomplete observer as full coverage.

## Decision
Continue existing in-flight million run unchanged; do not restart it merely to try this proposal. Start with single-pass reader/comparator and profiling because it avoids changing production or capture semantics. Delta observer is a separate higher-risk test-tool project, not yet verified. No new V9 completion claim, no runtime changes, no main/production writes. The owner must be told explicitly that this proposal has no measured speedup yet.
