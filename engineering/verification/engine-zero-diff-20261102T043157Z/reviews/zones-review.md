## Stage and dependency flow

S imports `as_decimal`, `policy_for` and `SOrderAuditMixin`. It receives immutable chronology, trend/opposite Reaction streams, trend Blues, A candidates, opposite Resets, analysis bounds and an initial geometry callback. Construction sorts A and Reaction chronology, builds Reset/Blue eligibility indexes and copies input collections (S 66-192). `detect` first audits every stopped A, then walks A in sorted order with mutable ownership windows. It finds the strict A stop and the first physical opposite Order; races independent Type-3 and Type-4 routes before Order formation, favoring Type-3 only on an exact decision-event tie; otherwise resolves Simple/Advanced Order-backed S (1228-1302). Frozen S objects retain A/Order/source/decision provenance. Shared accepted-Order stop reconciliation deduplicates physical `(FirstIndex, BreakIndex)`, prefers a richer exact-stop entry, sorts by `(cross, confirmation, First, Break)` and replaces S fields without rewriting the frozen S source (1305-1419).

E imports the shared Decimal/direction helpers and `OrderAuditEngineMixin`; Order creation/audit belongs to that mixin. Construction builds per-run cached arrays and an O(N log N) first-extreme sparse table, sorted confirmations and physical-identity indexes (70-227). `_zone` obtains direct/inherited/carried/post-stop routes, registers audit state, sorts all eligible physical Orders globally by exact stop and descending First, rejects disowned-S-only causes using the prospective E source, then materializes immutable E geometry (378-490). Discovery creates provisional independent chains from each S (788-881). Reconciliation groups physical source positions, processes a heap, validates mutable accepted ownership, regenerates fallback Orders/chains, applies family/number priority and records historical lineage (883-1215). Consumed-S continuation, branch replacement and independent-root restoration can modify accepted sets after ordinary detection (492-762). These are lifecycle-sensitive stages, not interchangeable cleanup passes.

Lifecycle imports the Decimal/physical identity helpers and accepted-audit preparation. It owns the one priority table, exact repeated-owner count, StopAll donor construction, stopped-A Order context, A/S eligibility, consumed-S evidence and final public lineage closure. `StopAllDetector.detect` merges S and E by source chronology, retaining exact decision/stop times for gates; same-source S events are processed after the E donor because the merge uses strict `<` (344-527). StopAll publication writes the detector `sequence_resets` once without rebuilding the E prefix (1298-1328). Final visibility restores referenced historical S/A before excluding occupied E/StopAll physical source candles (1428-1520).

Bridge ownership stays orchestration: `create_e_detector`, `calculate_full_direction_state`, Order_B feedback and final visibility call these owners (bridge 1891-2330, 2550-2610, 2635-2760). Full-direction work can reconstruct E multiple times for S eligibility, final audit and shared Order-stop reconciliation. The Order_B loop reuses Blue/A/initial S and reruns dependent stages; optimizations inside a detector and across detector construction have different lifetimes.

## Complexity and retained state

Let N be main candles, L lower candles, A A candidates, T/O trend/opposite Reactions, X opposite Resets, B Blues, S S candidates, Q all native plus regenerated E candidates examined, H parent-chain depth, K Order choices for a particular parent, and M combined lifecycle modules. These are static bounds/cost shapes, not measured hotspots. Shared lower-index first-cross queries use pruned segment-tree traversal; main-index mapping and timestamp bounds use bisection.

- S construction: sorting O(A log A + T log T + O log O + X log X + B log B), plus initial confirmation/Blue-time resolution. Chronology caching avoids many repeated lower scans but still constructs/cache-keys values. Several O(T/O/X/B) secondary arrays coexist. `_order_matches_after` (Order 2109-2128) can retain O(A*O) references for distinct A-stop suffixes; it copies the entire cached suffix to a fresh list, although its only discovered consumer selects element zero.
- S detection: an A is first scanned by `_audit_stopped_a` and later may repeat A-stop/first-Order lookup (S 1232-1256; Order 2166-2176). Ownership scans can contribute O(A squared). Candidate extrema remain linear main-candle slices (295-328), and Type-4 repeats an A-stop-origin range query for each aligned Reaction (467-535). Type-3 scans applicable Reset legs and computes each leg extreme (381-453). Consequently A*(X*N + T*N) is a conservative extremum-work shape before early exits/index restrictions. Lower source-event and Blue fallback scans are confined by timestamp windows but allocate lower-window slices.
- E construction: O(N log N) sparse-table time/position memory plus O(N+T+O+X) arrays. `_extreme_between` is O(log N) boundary mapping plus O(1) extreme query and preserves the first equal candle. `_zone` flattens O(K) choices and sorts O(K log K), then examines sorted choices until a valid creator wins, in addition to Order-owned query cost. Discovery/reconciliation multiply this by candidate and regeneration work.
- E reconciliation repeatedly scans S parents, numbered history, active owners and all candidate children. The nested eligible/active/child check (1049-1070) can be cubic in a static Q-sized candidate population; regeneration adds dynamic work. Parent recursion adds H and repeated membership/parent scans. No simple fixed bound on the entire pipeline is claimed from this module alone. Temporary result lists and accepted/candidate/reference indexes retain O(Q+S); branch ancestry work can reach O(Q*H) per replacement. Root restoration repeatedly scans result/S lists and builds projected source-time sets.
- StopAll sorting costs O(S log S + E log E). The merge is linear apart from repeated strict-stop queries and active-StopAll checks: up to O(E*activeStopAllCount) strict-stop invocations, plus armed-owner and final stop lookups.
- A splitting costs sorting plus O(A*M), with optional interior-head main-candle extrema and trend-Reaction scans (703-904). Invalid-head blocking is O(invalidA*O) (906-926). Consumed-S evidence performs O(S*E) owner/rank/latest checks plus sorts (929-1069). S module eligibility and public visibility repeatedly allocate concatenated prior-module lists, giving O(S*(E+S)) work/temporary allocation volume (1071-1296). A provenance visibility repeats stop-finder calls inside O(A*M) scans (1331-1376).

## Candidate opportunities, ordered by proof simplicity

All are proposals only. None is implemented, performance accepted or zero-difference verified. Measure before selecting a change; use exact stage, audit and serialized baselines for both directions.

1. **Remove demonstrably redundant candidate computation in S `_candidate_before_order` (744-786).** The full `_candidate_source(a_stop, First)` result is used only when the lower stop-candle remainder is empty; with a nonempty remainder, the routine rescans the later interval and discards the first full scan. Defer that full scan to the empty-remainder branch while preserving current invalid-range validation and supported-input error behavior. This saves one O(interval length) scan/allocation on the lower-data path with no new cache. Keep strict-first equal-price selection and intrabar remainder precedence. Invalid/malformed-input exception ordering must be specified before claiming complete public equivalence.
2. **First-win S-parent index built per E reconciliation/restoration pass.** Replace repeated `next` searches of the fixed S list (E 941-950, 1032-1035 and 724-725) with `setdefault((int(source_index), source_time), original_object)`. Construct within the pass, after externally supplied S state is final for that invocation; tests mutate `detector.s_zones` between calls. Preserve original references, first duplicate winner, and absent-parent behavior. Do not reuse the existing candidate dictionary: it intentionally has last-win semantics (913-916, 924).
3. **Invocation-local strict-stop cache for A provenance visibility and StopAll.** `visible_a_zones_after_module_boundaries` repeatedly resolves unchanged modules, including the selected dominant module again (1356-1366). The same file already demonstrates an identity-keyed local cache in S visibility (1147-1153). For frozen production S/E/StopAll and a deterministic chronology callback, use a per-invocation cache retaining module references, including None results; do not cache a stateful arbitrary callback without proving its contract. StopAll may similarly memoize `(start, Decimal level)` within one detect call. Direction and dataset are fixed by that invocation. Do not globalize it.
4. **Index first times for invalid-head blocking (906-926).** The result is a set of First timestamps satisfying `source <= First < exactStop`; a sorted per-invocation timestamp array with `bisect_left` at both ends can avoid testing every opposite Reaction for each invalid A. Preserve duplicate collapse, datetime values, strict upper end and callback invocation per A. Do not assume original Reaction order is time sorted; sort explicitly. Memory O(O); cost O(O log O + sum(log O + matched timestamps)).
5. **Chronological sweep for `s_zones_for_module_engines` (1071-1099).** Selection only requires the latest strictly earlier source from static E and accepted S. A sweep can avoid repeated concatenation/filter/max work. Preserve stable source-time sort, strict earlier eligibility, the first E among equal-source E objects, the first accepted S at an equal-source group, and E precedence over S at a true equal-source tie caused by `[E..., visibleS...]`. This is more complex than a local cache; require explicit tie fixtures before implementation.
6. **Profile-only larger candidates:** S first/last extreme query support, per-pass E child/active membership indexes, and prior-external lifecycle sweep. These can reduce the most obvious repeated scans but alter state access substantially. A running Type-4 extreme is unsafe unless nondecreasing queried Break positions are proved; confirmation order alone does not prove that. A shared E sparse table supports first ties only and cannot silently replace S's last-tie query. Reusing sparse preprocessing across rebuilt E detectors would broaden lifetime across Order_B and input contexts and requires a separate immutability/identity proof and peak-memory comparison.
7. **Tiny redundant allocation:** S `_trend_confirmation_times_sorted` sorts the already sorted confirmation projection (167-170). Both arrays are read-only by source search. Reusing the first projection preserves values/order; current monotonic Timsort is already linear, so this is allocation cleanup, not a claimed asymptotic speedup.

Order suffix materialization and repeated audit lookup are coordinated with the Order reviewer rather than proposed as a local S policy change. Initial geometry callback counts, physical object identity and native/canonical tie semantics must be preserved if that path changes.

## Numerical, chronology, identity and mutation constraints

- `as_decimal` returns an existing Decimal unchanged and otherwise uses `Decimal(str(value))`; do not substitute float arrays. DirectionPolicy strict-cross and better-extreme are strict `<`/`>`.
- S `_candidate_source` retains the first equal extreme; `_candidate_source_last`, Simple Break-to-Break, Type-3 and Type-4 retain the last equal main candle. `_candidate_event_time` then takes the first matching lower event after its not-before gate. A price-only comparison cannot establish equivalent provenance.
- S `_decision` returns None when Order stop and candidate crossing share the same lower position; it distinguishes qualifier times, fallback and Blue. Main-candle fallback has its own boundary semantics. Do not merge lower-data and no-lower-data logic casually.
- Type-3 beats Type-4 on exact decision tie. Advanced nested ownership precedes the Simple chronology override. Shared Order reconciliation uses `source_time <= cross < decision_event`, preserves S source, and chooses exact sorted physical Order keys. Equality changes would be behavioral changes.
- E sparse-table ties choose the first main position. Complete containing parent-stop and Order-stop candles participate in E source selection; lower chronology does not truncate their OHLC. The Order-consumption winner uses exact stop then *later* First; stable sort preserves route order on complete ties.
- Accepted E source sets, Order causes, sequence resets, active lists, regenerated candidates, numbered results and consumed owner sets mutate during reconciliation. Do not memoize `_zone`, `valid_order`, `parent_active`, independent-root eligibility, or cause-only query results by physical identity/ledger size alone.
- `sequence_resets` copies/maps and builds one sorted index; its setter clears four dependent caches. `_clear_order_audit` and cause-update operations clear relevant secondary caches in the mixin. Immutable chronology/canonical-stop caches intentionally survive these lifecycle invalidations. Any extra cache must follow the correct side of that boundary.
- Module identity, physical Order identity, source time alone, position alone and object identity serve different existing contracts. In A splitting, `stop_indices`/`stop_events` dicts have last-win duplicate behavior, while the interior branch's `next` search takes the first same identity; replacing that search with the existing dict can therefore change duplicate behavior. Preserve this distinction until authority/input invariants prove duplicates impossible.
- Public lineage restoration preserves original immutable references. Some replacements intentionally produce new frozen dataclass objects. `is` is used for removal/qualification and must survive a lookup refactor; reconstructing equivalent dataclasses is insufficient.
- Keep all provisional/historical evidence through consumed-S continuation, accepted-audit rebuild, independent-root restoration, StopAll donor selection and bridge projection. Do not compact solely because final public rows omit an object.
