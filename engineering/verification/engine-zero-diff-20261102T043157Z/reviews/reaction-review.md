## Ranked refactor opportunities and exclusions

1. **Use the already-owned lower segment index for A `_range_extreme` (167-199).** Replace the nonempty lower-window min/max scan with index range min/max, keeping the same `end+1us` bisects, earliest physical row, `_main_index` mapping, main-candle timestamp return and empty-lower fallback. This reduces each nonempty query from O(K) time/temporary references to O(log M)/O(1). Keep a fallback for absent custom index because callers/tests use duck-typed chronology elsewhere. This is an implementation candidate, not accepted or measured work. Required evidence: exact Decimal tuple/source identity agreement including ties, windows/empty windows, both directions and downstream stage/public equality.
2. **Use index first-cross for MarketChronology confirmation (1092-1137) and A Reset formation (218-228).** Both ask for an existing first strict high/low crossing on a bounded immutable sequence. Retain direction behavior, intrabar-clamp/A mode distinction, fallback Break/source time, and exact first-row ownership. Benefit must be established because the shared confirmation cache already removes identical repeats. New validation/exception behavior is outside zero-difference scope.
3. **Reduce Blue pending-list allocation without moving formation decisions (84-139).** A running strict-better extreme over eligible rows can retain the earliest equal owner while preserving exact confirmation cutoff and first break with eligible evidence. It saves auxiliary memory, not asymptotic time. Broader strike algorithm rewriting is higher risk and unneeded before measurement.
4. **Consider run-scoped main extrema indexing only if profiling justifies it.** Many Reaction minimum/maximum calls and A inherited windows repeat scans, but adding an index has memory/lifetime cost and source-tie obligations. Do not combine with chronology/state-machine restructuring.
